Dataflow Data & Analytics

What is it?

Fully managed service for stream and batch data processing using Apache Beam pipelines.

↩ click to reveal details

✅ Best Fit
ETL and ELT pipelines; real-time analytics; event stream processing; large-scale data transformation; unified batch and streaming workloads.
❌ Not a Good Fit
Small one-off scripts; workloads that require direct control over cluster infrastructure; simple SQL-only transformations that fit better in BigQuery.
⚖ Key Trade-off
Strong scalability and fully managed execution vs. less low-level infrastructure control and a steeper development model than simpler tools.
💰 Cost / Security
Autoscaling helps reduce unnecessary compute cost. Use private networking, service accounts with least privilege, and streaming engine options where appropriate for secure and efficient execution.
💡 Exam Scenario
A company needs to ingest millions of real-time events, transform them continuously, and load them into analytics storage without managing servers.
Dataflow — it is the managed choice for scalable stream and batch processing.
Dataproc Data & Analytics

What is it?

Managed Apache Spark and Hadoop service for running open-source big data workloads on Google Cloud.

↩ click to reveal details

✅ Best Fit
Existing Spark or Hadoop jobs; lift-and-shift big data processing; batch analytics; teams needing control over cluster configuration while still reducing operational effort.
❌ Not a Good Fit
Fully serverless event-driven pipelines where Dataflow is a better fit; small analytics jobs that do not justify cluster-based processing; workloads with no Spark or Hadoop need.
⚖ Key Trade-off
Greater compatibility with existing open-source ecosystems and more cluster control vs. more operational responsibility than fully managed serverless data processing.
💰 Cost / Security
Use ephemeral clusters and autoscaling to limit cost. Apply least-privilege IAM, secure service accounts, and private networking for data access and cluster isolation.
💡 Exam Scenario
An organization already has many Apache Spark jobs and wants to move them to Google Cloud quickly with minimal refactoring.
Dataproc — it is the best fit for managed Spark and Hadoop migration with minimal change.
Pub/Sub Data & Analytics

What is it?

Fully managed messaging and event ingestion service for asynchronous communication between producers and consumers.

↩ click to reveal details

✅ Best Fit
Event-driven architectures; decoupling services; ingesting telemetry and application events; buffering spikes before downstream processing.
❌ Not a Good Fit
Direct synchronous request-response interactions; workloads requiring complex queryable storage of messages; relational transactional workflows.
⚖ Key Trade-off
Excellent decoupling, elasticity, and durability vs. eventual consistency and additional complexity in downstream processing design.
💰 Cost / Security
Pub/Sub can absorb traffic bursts and reduce overprovisioning of consumers. Restrict publisher and subscriber permissions with narrowly scoped IAM roles and protect downstream consumers through private design patterns.
💡 Exam Scenario
A retail platform receives unpredictable order events and must ensure multiple backend systems process them independently without losing messages.
Pub/Sub — it decouples producers from consumers and supports durable asynchronous event delivery.
Datalab Data & Analytics

What is it?

Interactive notebook environment for exploring, analyzing, and visualizing data on Google Cloud.

↩ click to reveal details

✅ Best Fit
Data exploration; prototyping; notebook-based analysis; interactive work by analysts and data scientists using Google Cloud data services.
❌ Not a Good Fit
Production ETL orchestration; high-scale distributed processing; enterprise-grade scheduled data pipelines.
⚖ Key Trade-off
Fast and flexible interactive analysis experience vs. not being the right tool for productionized, scalable data pipelines.
💰 Cost / Security
Control access carefully because notebooks often touch sensitive datasets and credentials. Use least-privilege identities and avoid treating notebook environments as production data platforms.
💡 Exam Scenario
A data analyst needs an interactive environment to explore datasets, run experiments, and visualize results before productionizing a workflow.
Datalab — it is designed for interactive notebook-based data analysis and exploration.
Streaming Analytics Pipeline Data & Analytics

What is it?

Architecture pattern that uses messaging and stream processing services to ingest, transform, and analyze events in near real time.

↩ click to reveal details

✅ Best Fit
IoT telemetry; clickstream analysis; fraud detection; monitoring systems; use cases requiring low-latency insights.
❌ Not a Good Fit
Workloads that run once per day in large scheduled batches with no need for near-real-time results.
⚖ Key Trade-off
Faster insight and responsive analytics vs. more architectural complexity and higher operational sensitivity to pipeline design.
💰 Cost / Security
Process only the events and enrichments required to control cost. Protect event ingestion and downstream storage with IAM, encryption, and retention controls.
💡 Exam Scenario
A logistics company wants to process fleet sensor events in near real time and detect anomalies within seconds.
Use Pub/Sub for ingestion and Dataflow for real-time stream processing.
Batch Analytics Pipeline Data & Analytics

What is it?

Architecture pattern that processes large volumes of accumulated data at scheduled intervals rather than continuously.

↩ click to reveal details

✅ Best Fit
Daily reporting; historical transformations; large ETL jobs; cost-sensitive analytics where immediate results are not required.
❌ Not a Good Fit
Use cases with strict low-latency requirements, real-time alerting, or continuously updated dashboards.
⚖ Key Trade-off
Simpler and often cheaper than streaming for non-urgent data vs. delayed availability of insights.
💰 Cost / Security
Schedule jobs to align with lower-cost processing windows when possible. Secure data staging locations, cluster identities, and job permissions carefully.
💡 Exam Scenario
A business only needs overnight processing of the day’s sales records and wants to reuse existing Spark jobs.
Use a batch analytics pipeline with Dataproc for scheduled processing.
ETL with Dataflow Data & Analytics

What is it?

Managed extract-transform-load architecture using Dataflow to ingest, clean, transform, and load data into downstream analytical systems.

↩ click to reveal details

✅ Best Fit
Large-scale data transformation; event enrichment; schema normalization; pipelines combining batch and stream ingestion.
❌ Not a Good Fit
Tiny datasets or simple transformations that can be handled directly inside a warehouse with SQL alone.
⚖ Key Trade-off
Scalable managed data processing with unified programming model vs. more pipeline development effort than simpler point tools.
💰 Cost / Security
Dataflow autoscaling helps match resources to workload size. Use secure service accounts and minimize access to only the source and destination systems needed by the pipeline.
💡 Exam Scenario
A company must normalize raw event data from multiple sources before loading curated records into an analytics platform.
Use Dataflow to build the ETL pipeline because it handles transformation at scale in both streaming and batch modes.
Spark-Based Data Processing Data & Analytics

What is it?

Analytics architecture based on Apache Spark for distributed processing of large datasets, typically using Dataproc on Google Cloud.

↩ click to reveal details

✅ Best Fit
Existing Spark ecosystems; data engineering teams with Spark expertise; large batch transformations; ML preprocessing at cluster scale.
❌ Not a Good Fit
Small interactive analysis, simple messaging needs, or fully managed streaming designs where Dataflow is more appropriate.
⚖ Key Trade-off
Powerful open-source processing ecosystem and workload portability vs. greater operational management than serverless data processing services.
💰 Cost / Security
Use temporary clusters for jobs instead of permanent idle clusters where possible. Restrict cluster access and secure data paths through private connectivity and IAM.
💡 Exam Scenario
A company has a mature Spark codebase and wants to process petabyte-scale historical logs in Google Cloud without rewriting everything.
Use Dataproc to run the Spark-based processing workloads with minimal refactoring.
Asynchronous Event Ingestion Data & Analytics

What is it?

Data architecture pattern where events are accepted and stored durably before downstream processing happens independently.

↩ click to reveal details

✅ Best Fit
Bursty producers; independent downstream consumers; resilient ingestion layers; fan-out architectures with multiple subscribers.
❌ Not a Good Fit
Workflows where the client must wait synchronously for all downstream actions to complete before receiving a response.
⚖ Key Trade-off
Better durability and decoupling vs. increased eventual consistency and downstream orchestration complexity.
💰 Cost / Security
This pattern reduces the need to overprovision consumers for spikes. Control who can publish and subscribe, and protect event retention policies appropriately.
💡 Exam Scenario
An application receives highly variable upload activity and several systems need to process each event independently at their own speed.
Use Pub/Sub for asynchronous event ingestion and decoupled fan-out processing.
Interactive Data Exploration Data & Analytics

What is it?

Notebook-oriented data analysis workflow that allows users to query, inspect, visualize, and experiment with datasets interactively.

↩ click to reveal details

✅ Best Fit
Prototyping, ad hoc exploration, analyst workflows, experimentation before building production data pipelines.
❌ Not a Good Fit
Scheduled production processing, SLA-bound transformations, or large-scale distributed production workloads.
⚖ Key Trade-off
Very flexible and user-friendly for exploration vs. weak suitability for hardened, repeatable, production-grade operations.
💰 Cost / Security
Notebook sessions should be controlled tightly because they may expose broad dataset access. Use least-privilege identities and avoid storing secrets directly inside notebooks.
💡 Exam Scenario
A data team wants to investigate a new dataset interactively before deciding how to productionize the pipeline.
Use Datalab for interactive exploration, then move production workflows to the appropriate managed processing service.
Decoupled Analytics Architecture Data & Analytics

What is it?

Architecture approach that separates ingestion, processing, storage, and consumption into independent layers connected through durable interfaces.

↩ click to reveal details

✅ Best Fit
Scalable data platforms; multi-team environments; evolving analytics ecosystems; workloads where independent scaling and failure isolation matter.
❌ Not a Good Fit
Very small single-purpose pipelines where a layered architecture would add unnecessary complexity.
⚖ Key Trade-off
Better scalability, resilience, and maintainability vs. more design complexity and more components to govern.
💰 Cost / Security
Decoupling can reduce waste by allowing each layer to scale independently. Apply IAM boundaries and data access controls separately at ingestion, processing, and storage layers.
💡 Exam Scenario
A company wants to ingest events once, process them in multiple ways, and allow several downstream systems to evolve independently.
Use a decoupled analytics architecture with Pub/Sub for ingestion and separate processing services such as Dataflow or Dataproc as needed.
Data Processing Service Selection Data & Analytics

What is it?

Architecture decision process for choosing between Dataflow, Dataproc, Pub/Sub, and Datalab based on workload type and operational needs.

↩ click to reveal details

✅ Best Fit
Exam scenarios where multiple analytics tools appear possible and the correct answer depends on whether the need is messaging, serverless processing, cluster-based processing, or interactive analysis.
❌ Not a Good Fit
Choosing a tool based only on familiarity instead of workload pattern, team skillset, and operational requirements.
⚖ Key Trade-off
Correct service selection improves cost, scalability, and simplicity; poor selection increases operational burden and redesign risk.
💰 Cost / Security
Pick the simplest managed option that satisfies the need. Use least-privilege access and avoid exposing processing systems or notebook environments unnecessarily.
💡 Exam Scenario
A question asks for the best service for durable event ingestion, another for managed stream processing, another for existing Spark jobs, and another for interactive notebook exploration.
Pub/Sub for messaging ingestion, Dataflow for managed stream or batch processing, Dataproc for Spark or Hadoop workloads, and Datalab for interactive analysis.
